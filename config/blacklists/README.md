# Curated exclusion lists

Most exclusion lists are fetched at runtime from a plain BED URL by
`run_procap_pipeline.py --fetch-genomes` (see `blacklist_url` in
`config/genomes.yaml`). This directory holds the exceptions — small, curated
sets that are not distributed as BED and so are versioned here instead.

## TAIR10.Klasfeld.Excludable.bed.gz

83 regions, *A. thaliana* TAIR10. Arabidopsis is not an ENCODE/modENCODE organism,
so there is no Boyle-Lab or ENCODE list for it — but this set was produced by
running **the same Boyle-Lab/Blacklist software** used for dm6, ce11 and mm10,
over 20 Arabidopsis input samples. excluderanges describes it identically to the
Boyle sets: "Defined by the Boyle-Lab/Blacklist software, High Signal and Low
Mappability regions". It is therefore the methodologically comparable choice.

- Source: Zenodo [10.5281/zenodo.21480958](https://doi.org/10.5281/zenodo.21480958),
  file `TAIR10.Klasfeld.arabidopsis_Excludable_20inputs.rds`
- Method: Klasfeld et al., [10.1101/2022.02.27.482177](https://doi.org/10.1101/2022.02.27.482177)
- **Chromosome names were stripped of their `chr` prefix.** The published set uses
  `chr1`–`chr5`; the Ensembl Plants TAIR10 FASTA this repo aligns to uses bare
  `1`–`5`, and `extract_loci` matches names literally, so unstripped the list
  would exclude nothing. Same normalisation the yeast download scripts apply.
- Verified: 83 regions, 2,854,600 bp (2.40% of the nuclear genome — in line with
  dm6 at 2.60%), all coordinates within TAIR10 chromosome lengths, sorted.

### Why not the peakPass set

`TAIR10.Wimberley.predicted_excluded_list_sorted_0.6` (887 regions, 2.08%) was
used initially and then rejected. peakPass **predicts** exclusion regions with a
machine-learning classifier over annotation features (assembly gaps, genes,
RepeatMasker repeats, alignability) rather than measuring artefactual signal in
real input samples, and it was trained for ChIP-seq. Two problems for this repo:

1. It is not comparable to the Boyle-Lab lists used for every other species — a
   different tool and a different philosophy (predicted vs. empirical).
2. **Gene annotation is one of its input features.** For a model of transcription
   initiation that is a circularity hazard: exclusion regions partly determined by
   gene structure, applied to training data whose labels are TSSs at gene starts.

Also available in the same Zenodo record, not used:
`TAIR10.Klasfeld.arabidopsis_greenscreen_20inputs` (36 regions, green screen
pipeline rather than Boyle-Lab software), `TAIR10.UCSC.araTha1.gap` (357 regions,
assembly gaps only — not artefact regions), and
`TAIR10.Wimberley.predicted_excluded_list_sorted_0.6` (887, above).

Regenerate (needs R; base R only, no Bioconductor — the GRanges slots are read
directly, so `GenomicRanges` is not required just to deserialise):

```bash
curl -sL -o TAIR10.rds \
  "https://zenodo.org/records/21480958/files/TAIR10.Klasfeld.arabidopsis_Excludable_20inputs.rds"

Rscript -e '
x  <- readRDS("TAIR10.rds"); a <- attributes(x)
sn <- attributes(a$seqnames); rg <- attributes(a$ranges)
chrom <- rep(as.character(sn$values), sn$lengths)
start <- as.integer(rg$start); width <- as.integer(rg$width)
# GRanges is 1-based inclusive; BED is 0-based half-open
bed <- data.frame(chrom, start = start - 1L, end = start - 1L + width)
write.table(bed, "TAIR10.raw.bed", sep = "\t", quote = FALSE,
            row.names = FALSE, col.names = FALSE)'

sed 's/^chr//' TAIR10.raw.bed | sort -k1,1 -k2,2n \
  | bgzip > TAIR10.Klasfeld.Excludable.bed.gz
```
